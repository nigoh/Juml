# ADR-0003: Cost-tiered agent orchestration: opus/fable を司令塔、sonnet/haiku をワーカーにする

- **Status**: Accepted
- **Date**: 2026-09-05
- **Deciders**: リポジトリオーナー + Claude Code セッション
- **Related**: ADR-0002, `orchestrate` スキル, `.claude/workflows/*.js`, `.claude/agents/*.md` の `model:`

## Context: 背景

`bug-hunt` / `render-sweep` / テスト監査のラウンドを最上位モデルで回したところ、
サブエージェントがセッション上限・モデル別上限に頻繁に当たり、ファインダーや検証者が
途中で落ちて `resumeFromRunId` で再開する手戻りが多発した。一方、ワーカーがやっている
仕事の大半は「ハーネスを走らせる」「レポートを読む」「コードを読んで根拠を出す」といった
定型作業で、最上位モデルの推論力を必要としない。ユーザーからも「コストを下げたい。
opus や fable を司令塔に、作業は sonnet や haiku に」という要望がある。

## Decision: 決定

| 層 | 担当 | モデル | 典型タスク |
|---|---|---|---|
| 0. 決定論 | スクリプト / Hook / Gradle | なし | ハーネス実行、品質ゲート、レンダリング総ざらいの実行本体 |
| 1. 軽ワーカー | サブエージェント / Workflow の `agent()` | **haiku** | ペルソナ操作（newcomer / power-user）、レポート要約、スイープ実行、機械的な列挙 |
| 2. 判断ワーカー | 同上 | **sonnet** | ドメイン知識が要るペルソナ、bug ファインダー、敵対的検証、バックログ集約、テスト実装（`test-engineer`） |
| 3. 司令塔 | メインループ | **opus / fable** | 計画、対象の絞り込み、既知の除外、最終 triage、修正、commit、ADR |

運用ルール:

1. **Workflow の `agent()` は `model` を明示する**（省略するとメインループのモデルを継承して
   最上位になる）。ファインダー / 検証は `sonnet`、実行系は `haiku`。`effort` は検証のみ `high`。
2. **サブエージェント定義（`.claude/agents/*.md`）は frontmatter の `model:` で階層を固定する**。
   既定は `sonnet`、ペルソナの軽ワーカーは `haiku`。
3. **司令塔は生ログ・生レポートを読まない**。ワーカーが構造化した所見だけを受け取る
   （司令塔のコンテキストと推論コストを守る）。
4. **修正と commit は司令塔が直列に行う**（並列書き込み競合の回避）。ワーカーはコードを直さない。
5. ワーカーの出力に **根拠（repro / evidence / file:line）を必須** にし、司令塔は根拠が無い
   所見を捨てる。安いモデルの偽陽性は検証層（sonnet, 反証プロンプト）で落とす。
6. 例外: 最上位モデルでしか通らない設計相談は司令塔が自分で行う（ワーカーに opus を割り当てない）。

## Options considered: 検討した選択肢

| 案 | 概要 | 利点 | 欠点 |
|---|---|---|---|
| A（採用） | 階層固定（司令塔 = 最上位、ワーカー = sonnet/haiku） | コストと上限の両方が下がる。役割が明確 | 安いワーカーの偽陽性を検証層で吸収する必要 |
| B | 全部最上位モデル | 個々の判断品質は最高 | 上限に当たり回らない（実績）。コスト高 |
| C | 全部 haiku | 最安 | 敵対的検証・修正の品質が不足 |
| D | 動的にモデルを選ぶ（失敗したら格上げ） | 適応的 | 再現性が下がり、ワークフローの `resume` と相性が悪い |

## Consequences: 結果・影響

- **良くなること**: ラウンドが最後まで回る。同じ予算でペルソナ数・ラウンド数を増やせる。
- **引き換えに受け入れること**: ワーカーの所見はやや粗い。検証層と「根拠必須」で補う。
- **フォローアップ**: 既存ワークフロー（`bug-hunt` / `render-sweep`）の `agent()` に `model` を明示済み。
  新しいワークフロー / サブエージェントを足すときはこの表に従う。
