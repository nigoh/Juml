# ADR-0004: Diagram-kind dropdown over three-tier menus: 3 段メニューを図種ドロップダウンに置き換える

- **Status**: Accepted
- **Date**: 2026-09-04（PR #162 でマージ済みの決定を遡って記録）
- **Deciders**: リポジトリオーナー（「c 案だね」）+ Claude Code セッション
- **Related**: PR #162, `.claude/rules/gui-tab-architecture.md`, `DiagramKindChooser`, `ToolBarBuilder`

## Context: 背景

UML GUI のメニューが「メニューバー → 図種カテゴリ → 図種」の 3 段になっており、
「どこに何があるか分からない」「複雑で触りづらい」という声があった。
図種はアクティブなタブの状態と常に同期している必要があり（ラジオメニュー / ツールバー /
コントローラの `currentKind`）、導線を減らすと同期の経路も減らせる。

## Decision: 決定

- ツールバーに **図種ドロップダウン**（`DiagramKindChooser`）を 1 つ置き、全図種を平坦に選べるようにする（C 案）。
- メニューバーの図種ラジオは残すが補助扱い。ドロップダウン / ラジオ / `controller.currentKind` は
  常にアクティブタブの図種と一致する（GuiMonkey の不変条件として機械検査する）。
- 図タブが非アクティブ（固定ユーティリティタブ / エディタタブ）のときはドロップダウンを
  プレースホルダ表示にし、無効な図種はパレットからも開けない。

## Options considered: 検討した選択肢

| 案 | 概要 | 利点 | 欠点 |
|---|---|---|---|
| A | 3 段メニューのまま並べ替え | 変更が小さい | 根本的に段数が減らない |
| B | 図種ごとのツールバーボタン列 | 一目で全部見える | 図種が増えると溢れる。横幅依存 |
| C（採用） | 図種ドロップダウン 1 つ + 補助メニュー | 1 クリックで全図種。現在の図種が常に見える。拡張に強い | ドロップダウン内の並び・グループ分けの設計が必要 |

## Consequences: 結果・影響

- **良くなること**: 図種の切替が 1 段になり、現在の図種が常に表示される。
- **引き換えに受け入れること**: 同期経路（タブ ↔ ドロップダウン ↔ ラジオ ↔ コントローラ）の
  回帰リスク。PR #163 のバグ枯らしと GuiMonkey の不変条件検査で守る。
- **フォローアップ**: ドロップダウンのグループ分け・検索は `docs/persona-backlog.md` の候補。
