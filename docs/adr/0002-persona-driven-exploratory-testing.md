# ADR-0002: Persona-driven exploratory testing: ペルソナ・エージェントが実際にアプリを動かして育てる

- **Status**: Accepted
- **Date**: 2026-09-05
- **Deciders**: リポジトリオーナー + Claude Code セッション
- **Related**: ADR-0003, `persona-explore` スキル, `.claude/workflows/persona-explore.js`,
  `.claude/agents/persona-*.md`, `src/test/java/juml/app/uml/GuiMonkey*.java`, `docs/persona-backlog.md`

## Context: 背景

PR #163 までのバグ枯らしでは、使い捨ての GUI monkey ハーネス（scratchpad）で 20 種の操作面を
機械的に叩き、約 26 件の確定バグを修正した。しかしそのハーネスはリポジトリ外にあり再利用できず、
また「例外が出るか」しか見ないため、**操作性の問題や機能の不足**（ユーザーが困ること）は
拾えなかった。ユーザーからは「ペルソナのエージェントを作って実際に動かし、ランダムテストや
不足機能の洗い出しなど、アプリの成長・熟成につながる仕組みが欲しい」という要望がある。

制約: GUI テストは Xvfb 上でしか動かない。1 回のハーネス実行は 15〜25 分。
サブエージェントの実行はモデルのレート制限に当たりやすい（ADR-0003）。

## Decision: 決定

1. **探索ハーネスをリポジトリに昇格させる**: `src/test/java/juml/app/uml/GuiMonkey`（+ `Runtime` /
   `Scenarios` / `Fuzz`）。JUnit テストではなく `main` を持つ探索用クラスで、`compileTestJava` で
   コンパイルされ `gradle test` では走らない。`--scenarios` / `--seed` / `--fuzz N` /
   `--shots <dir>` を持ち、所見を JSON、画面を PNG で残す。
2. **ランダムテスト（S21 fuzz）を標準装備する**: シード付きで操作プールから乱択し、同じシードで
   同じ操作列を再現できるようにする（再現性のない所見は修正できない）。
3. **ペルソナをサブエージェントとして定義する**（`.claude/agents/persona-*.md`）: 初見ユーザー /
   パワーユーザー / Android 開発者 / AOSP 解析者。各ペルソナは「誰か・何を重視するか・
   どのシナリオと CLI をどの順で試すか」を持ち、**観察した事実だけ** を
   `bug` / `usability` / `missing-feature` に分類して返す（コードは直さない）。
4. **ワークフローで回す**（`persona-explore.js`）: Explore（ペルソナ並列）→ Verify（bug の敵対的
   反証）→ Triage（usability / missing-feature をバックログ項目に集約）。修正・commit・バックログ
   更新は司令塔（メインループ）が直列に行う。
5. **成長バックログを永続化する**: `docs/persona-backlog.md`。ラウンドをまたいで重複を除外し
   （`known`）、状態（open / in-progress / done / rejected）を司令塔が更新する。
   バックログ項目の実装可否はユーザーが決める（自動実装しない）。
6. **停止条件**: 確定バグ 0 件のラウンドが 1 回続いたら停止。バックログは無限に増やさない。

## Options considered: 検討した選択肢

| 案 | 概要 | 利点 | 欠点 |
|---|---|---|---|
| A（採用） | 決定論ハーネス + ペルソナ・ワーカー + 司令塔 | 安い層が大量に触り、判断が要る所だけモデルを使う。再現性あり | ハーネスの保守が必要 |
| B | LLM エージェントが Robot を直接操作する | 柔軟 | 1 操作ごとに推論コスト。再現性が無く、レート制限で止まる |
| C | 静的レビュー（`bug-hunt`）だけで使い勝手も見る | 追加実装不要 | 「実際に触って困る」ことは静的には出にくい（PR #163 で実証） |
| D | AssertJ-Swing の回帰テストを増やすだけ | CI で守れる | 既知の振る舞いしか守れず、未知の問題や不足機能は出ない |

## Consequences: 結果・影響

- **良くなること**: 「触って困ること」が継続的に集まり、確定バグは即修正、それ以外は
  受け入れ条件付きのバックログとして残る。ペルソナ追加は Markdown 1 枚 + カタログ 1 行。
- **引き換えに受け入れること**: ハーネスは `UmlMainFrame` の内部フィールドへリフレクションで
  触る（探索用途に限定。確定した問題は公開振る舞いで回帰テスト化する）。1 ラウンド 20〜40 分。
- **フォローアップ**: ペルソナの追加（CLI 自動化ユーザー、アクセシビリティ）、ハーネスへの
  シナリオ追加（設定ダイアログ、エクスポート）、バックログ上位の実装判断。
